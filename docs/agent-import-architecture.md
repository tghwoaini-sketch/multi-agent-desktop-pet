# Agent 任务导入架构

## 当前闭环

1. Agent 根据用户描述生成 `xiaobu.task.v1` JSON 任务包。
2. 用户把 JSON 文件拖入“创建任务”页面，或直接粘贴内容。
3. 页面校验版本、任务类型、标题和步骤结构。
4. 任务被标准化后写入本地任务库。
5. 首页、周目标和通用执行器读取同一份任务记录。

## 为什么先用任务包

- Agent 不需要操作网页，只要稳定生成结构化文件。
- 网页不需要接入模型密钥，数据也不会离开本机。
- 手动创建、文件导入和未来 API 导入共用同一个模型。
- 格式带版本号，未来升级字段时可以迁移旧数据。

## 给 Codex 的固定指令

> 请根据我的目标生成一个小步修仙复杂任务包。严格输出 `xiaobu.task.v1` JSON；每个步骤包含 title、goal、minutes、xp、checklist，步骤数量控制在 3–10 个。把结果保存为 `.task.json` 文件，不要修改网页代码。

## 未来扩展

- 本地一键：Codex 把 `.task.json` 写入指定导入目录，桌面包装器监听目录。
- MCP：提供 `create_task`、`update_task`、`list_tasks` 工具及严格输入输出 schema。
- 云端：把本地存储适配器替换为账号数据库；任务模型和执行器保持不变。
